## Antes de entregar

- Contrastar alcance, estructura y fixtures web con el enunciado y la rúbrica vigentes.
- Seguir la guía de ejecución y conservar resultados crudos, manifiestos y fecha de ejecución.
- Comprobar que matriz, reportes y conclusiones corresponden al código que se entrega.
- Identificar en GitHub la rama o versión entregada y permitir acceso a la docente.
- Verificar en [Actions](https://github.com/granitespinoza/qolqe-g4-qa/actions) commit, intento, jobs y artefactos del workflow principal.
- Descargar y extraer el artefacto final; abrir su portal y comprobar enlaces a reportes, pruebas y matriz. Los artefactos del workflow se retienen siete días.
- Comprobar que el archivo solicitado para Canvas y los enlaces de GitHub apuntan a la versión presentada. La consigna vigente determina el formato y plazo.

## Interpretación

Los FAIL conocidos permanecen visibles. Una aprobación del gate por Escenario A corresponde a la política documentada para la instancia académica; no equivale a todos los tests aprobados ni acredita aceptación docente de esa política.

El recorrido breve, la regresión completa y una ejecución remota tienen alcances diferentes. La documentación y el HTML pueden contener evidencia histórica; identificarlos como tales hasta verificar una ejecución de la versión entregada.
